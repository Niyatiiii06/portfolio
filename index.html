TelecomDocQA

Ask a question about the 5G specs and get an answer that cites the page.

What it does

Question answering over 2,264 pages of 3GPP 5G specifications, split into 7,660 section-aware chunks. It combines dense search (ChromaDB) with BM25 keyword search through Reciprocal Rank Fusion, then a cross-encoder reranks the results. Every answer cites its spec, section and page.

How I checked it

A 68-question test set, 10 of them unanswerable on purpose, scored by an LLM judge from a different model family than the one answering.

What I shipped

A FastAPI service with Pydantic validation, streaming responses, an answer cache and rate limiting. 146 pytest tests, and a GitHub Actions pipeline that builds and smoke-tests the Docker image on every push. To fit free CPU hosting I moved both models from PyTorch to ONNX Runtime and rewrote BM25 as a compact inverted index. Keyword-index memory went from 76 MB to 23 MB with identical rankings, and Recall@5 stayed at 0.93.

FraudRiskIntel

Fraud scoring on 6.36M transactions, with every flag explained.

What it does

Scores 6.36M PaySim mobile-money transactions, where 0.13% are fraud. Features come from SQL in DuckDB, using window functions over each receiving account's past activity. A LightGBM model is trained on a time-based split, so it is always tested on a later period.

How I checked it

I held out the last 15% of the month, 408K transactions, and used it once. The baseline is a rules system tuned on the validation set. I set the review cut-off from business costs, counting a missed fraud as 50 times a false alarm.

What I found

The near-perfect scores often reported on PaySim come from a balance artifact in the simulator. Using it gives a PR-AUC of 0.9999 and without it the score is 0.35. I left those features out of the final model.

What I shipped

SHAP explanations for every flag, PSI drift monitoring, MLflow run tracking, and a FastAPI endpoint that returns the probability, the decision and the top reasons. 57 pytest tests, Docker, GitHub Actions CI and a live Streamlit demo.

Dependency Update Agent

Checks whether upgrading a Python dependency is likely to break your repository.

What it does

It connects what a library's changelog says with how your code actually uses that library. Hybrid retrieval, ChromaDB dense search plus BM25, runs over changelog and release-note data to find both semantic and exact-match evidence. An AST-based code search finds function definitions, calls and imports across the repository.

How it fits together

A LangChain tool-calling agent uses the retrieval and the code search as tools, returns structured Pydantic outputs, keeps its history in SQLite and runs behind a Streamlit interface.
